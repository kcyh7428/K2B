# Prepare Keith-facing ship brief

Use this when Keith asks what changed, what shipped, whether he is affected, or whether Claude Code still works.

## What you will notice

Plain-English change in Keith's day-to-day K2B experience.

## What stays the same

Compatibility lanes and habits Keith can keep using.

## What is not included yet

Later ships or unsolved gaps. Be explicit so K2B does not overclaim.

## What to do now

Switch tools, restart, test one workflow, run sync, or do nothing.

## Under the hood

Commits, files, hooks, tests, provider names, and other implementation detail.

## Risk / rollback

One short sentence when relevant.

## Style Rule

Lead with user impact. Use before/after examples and "this means / this does not mean" wording. Do not lead with file counts or commit stats unless Keith asks for codebase detail.
